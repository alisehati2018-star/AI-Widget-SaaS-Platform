# راهنمای بهره‌برداری — مدیریت AI پلتفرم (ارائه‌دهندگان، مدل‌ها، پیکربندی، سود)

این راهنما برای اپراتور پلتفرم است: از صفر تا یک سیستم AI درآمدزا — اتصال ارائه‌دهنده، کشف و ایمپورت مدل، بستن زنجیره‌های مسیریابی، قیمت‌گذاری، و پایش سود. سه صفحهٔ ادمین این سیستم: **ارائه‌دهندگان AI** (`/admin/providers`)، **مدل‌ها** (`/admin/models`)، **پیکربندی AI** (`/admin/ai-config`).

## ۱) پیش‌نیاز یک‌باره (استقرار)

```bash
# ۱. استک را بالا بیاورید و مایگریشن‌ها را اعمال کنید (شامل 0019/0020)
docker compose -f infra/docker-compose.yml up -d
python scripts/apply_migrations.py

# ۲. اولین ادمین را بسازید (توکن اپراتور از .env → ADMIN_TOKEN)
curl -X POST $HOST/admin/auth/bootstrap \
  -H "x-admin-token: $ADMIN_TOKEN" -H "content-type: application/json" \
  -d '{"email":"you@example.com","password":"یک-رمز-قوی","full_name":"Operator"}'
```

سپس در `/admin/login` وارد شوید. تنظیمات env کامل در `.env.example` مستند است.

## ۲) اتصال ارائه‌دهنده (مثال: OpenRouter)

صفحهٔ **ارائه‌دهندگان AI**:
1. از ردیف قالب‌ها (OpenRouter، OpenAI، Google، DeepSeek، Groq، Bynara، AvalAI، Conduit) قالب را انتخاب و **کلید API** را وارد کنید — base_url و نوع کشف خودکار پر می‌شود.
2. دکمهٔ **بررسی اعتبار** همان‌جا سلامت کلید را زنده تست می‌کند (برای OpenRouter موجودی واقعی حساب را می‌آورد؛ برای بقیه سلامت کلید).
3. کلید غلط ⇒ پیام خطای واضح (مثلاً «Credit check failed: 401») — هیچ موفقیت ساختگی‌ای وجود ندارد.

نکته‌ها:
- **کلید API فقط-نوشتنی** است: بعد از ذخیره فقط ۴ رقم آخر دیده می‌شود؛ برای تعویض، مقدار جدید بدهید؛ خالی یعنی «همان قبلی بماند».
- `priority` ترتیب نمایش/ترجیح ارائه‌دهنده، `max_retries` و `retry_backoff_ms` رفتار تلاش مجدد هر endpoint را کنترل می‌کند.
- ارائه‌دهندهٔ دارای مدل قابل حذف نیست (گارد حذف) — اول مدل‌ها را حذف/منتقل کنید.

## ۳) کشف و ایمپورت مدل‌ها

صفحهٔ **مدل‌ها** (تب هر ارائه‌دهنده):
1. **کشف مدل‌ها** فهرست زندهٔ مدل‌های ارائه‌دهنده را می‌آورد (openai-compatible / openrouter / google / bynara / conduit).
2. مدل‌های موردنظر را انتخاب و **ایمپورت گروهی** کنید — `context_window` و `is_free_tier` در صورت وجود خودکار پر می‌شود.
3. قیمت هر مدل (`$/1M` توکن ورودی/خروجی) را از سایت ارائه‌دهنده وارد/اصلاح کنید — **این عدد پایهٔ محاسبهٔ سود است**.
4. `modality` مدل را درست بگذارید: `chat` (گفت‌وگو/تحلیل) · `embedding` (جست‌وجوی معنایی؛ `dims` باید با `EMBEDDING_DIMS` استقرار یکی باشد) · `rerank` (بازرتبه‌بندی نتایج).
5. حذف گروهی، مدل‌های بسته‌شده در زنجیره را رد می‌کند و می‌گوید در کدام زنجیره‌اند.

## ۴) بستن زنجیره‌های مسیریابی (پیکربندی AI)

برای هر وظیفه یک زنجیرهٔ مرتب می‌بندید — اولین مدل primary است و بقیه failover:

| وظیفه | مصرف‌کننده | modality لازم |
|---|---|---|
| `chat` | دستیار ویجت فروشگاه‌ها (پرسش‌های سخت/synthesis) | chat |
| `analyst` | تحلیلگر ادمین (کنسول agent + بینش) | chat |
| `embedding` | بردارسازی جست‌وجوی معنایی (ایندکس + کوئری) | embedding |
| `rerank` | بازرتبه‌بندی اپلیکیشن-ساید نتایج جست‌وجو | rerank |

- کنار هر binding نشان **اهلیت** زنده است: مدل غیرفعال / ارائه‌دهندهٔ غیرفعال / بدون کلید — این‌ها در زمان اجرا skip می‌شوند.
- **کلید سراسری failover**: خاموش ⇒ فقط primary هر زنجیره امتحان می‌شود (به‌جز ضامن محلی که هرگز حذف نمی‌شود).
- زنجیرهٔ chat اگر مدل محلی نداشته باشد، مدل محلی env به‌عنوان ضامن انتها خودکار اضافه می‌شود (وابستگی سخت به vendor هرگز).
- **نردبان هزینه**: پرسش‌های FAQ با قالب (مجانی) → پرسش‌های جست‌وجویی با خود نتایج (بدون LLM) → پرسش‌های synthesis اول مدل محلی → فقط پرسش‌های سخت سراغ زنجیرهٔ پولی می‌روند. یعنی مدل پولی فقط جایی خرج می‌شود که لازم است.
- **rerank**: بستن این زنجیره یعنی روشن‌کردن بازرتبه‌بندی اپ‌ساید (با failover و degrade به ترتیب قبلی). مسیر جایگزین ES-ساید (`RERANK_ENABLED` + inference endpoint روی کلاستر) جداست؛ اگر هر دو باشند اپ‌ساید برنده است.

## ۵) قیمت‌گذاری و سود

- **قیمت‌گذاری** (`/admin/ai-config`): ارزش دلاری هر کردیت (`usd_per_credit`)، **حاشیهٔ سود** (`margin_percent`)، قیمت flat هر جست‌وجو، و انتساب هزینهٔ مدل محلی (برق/استهلاک؛ صفر = سود خالص).
- فرمول هر نوبت گفت‌وگو: `COGS = tokens_in×in$/1M + tokens_out×out$/1M` → `کردیت مشتری = COGS×(1+margin)/usd_per_credit`.
- **مالی** (همان صفحه): مصرف کردیت (= درآمد به ارزش کردیت)، هزینهٔ واقعی ارائه‌دهنده (COGS)، **سود ناخالص**، به تفکیک روز/مدل/تنانت. مصرف ۳۰روزهٔ هر ارائه‌دهنده روی صفحهٔ ارائه‌دهندگان هم هست.
- **سیاست کردیت ثبت‌نام** (کارت روی صفحهٔ پلن‌ها): کردیت خودکار هدیهٔ هر ثبت‌نام تازه — قابل تنظیم/خاموش‌کردن.
- کش L1/L2 یعنی سوال تکراری هزینهٔ صفر دارد؛ بودجهٔ کیف پول (`WalletBudgetGuard`) جلوی مصرف بیش از موجودی تنانت را در مسیر درخواست می‌گیرد.

## ۶) عیب‌یابی سریع

| علامت | علت محتمل | کجا ببینید |
|---|---|---|
| «هیچ ارائه‌دهندهٔ واجد شرایطی نیست» در ai-config | مدل/ارائه‌دهنده غیرفعال یا کلید ندارد | نشان اهلیت همان ردیف |
| کشف مدل خطا می‌دهد | کلید/شبکه/آدرس پایه | پیام خطا متن پاسخ vendor را دارد؛ با «بررسی اعتبار» جدا تست کنید |
| پاسخ دستیار همیشه «این محصولات را پیدا کردم…» | زنجیرهٔ chat خالی/ناسالم است و سیستم به fallback جست‌وجو degrade کرده | اهلیت زنجیرهٔ chat + `/admin/health` (زیرساخت محلی) |
| finance خالی است | هنوز مصرفی ثبت نشده (فقط نوبت‌های واقعی LLM/جست‌وجو ثبت می‌شوند) | `usage_events` بعد از اولین گفت‌وگو پر می‌شود |
| embedding بسته نمی‌شود | `dims` مدل با `EMBEDDING_DIMS` استقرار نمی‌خواند | پیام 422 همان لحظه می‌گوید |

`GET/POST /admin/ai/providers` · `POST .../from-template` · `POST .../{id}/discover` · `POST .../{id}/models/import` · `POST .../{id}/check-credit` · `GET/POST /admin/ai/models` (+`/bulk-delete`) · `GET/PUT /admin/ai/routes/{task}` · `GET/PUT /admin/ai/routing-settings` · `GET/PUT /admin/ai/pricing` · `GET /admin/ai/finance?days=N` · `GET/PUT /admin/credit-policy`.
