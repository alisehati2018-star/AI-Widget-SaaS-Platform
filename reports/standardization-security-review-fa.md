- اجرای فعلی: `0 file(s) over 400 lines` ✅

### تأیید صحت (بدون رگرسیون)
هر تفکیک با روش زیر تأیید شد (نمونه برای `admin.py`):
```
diff <(routes_before) <(routes_after) && echo "IDENTICAL - no route regressions"
```
نتیجه برای هر ۷ تفکیک: **صفر اختلاف مسیر**. به‌علاوه:
- `ruff check .` → پاک (۰ خطا)
- `mypy packages services eval scripts` → پاک (۱۴۷ فایل)
- `pytest -q` → ۱۶۷ pass / ۴۶ skip (بدون تغییر نسبت به قبل از تفکیک)
- ایمپورت‌های سرگردان به توابع جابه‌جاشده (`_require_tenant`، `current_principal`، `admin_current_principal`، `_email_invoice`، …) در تمام فایل‌های وابسته (`billing.py`، `admin_operators.py`، `admin_monitoring.py`، `admin_common.py`، تست‌ها) پیدا و اصلاح شدند.

## ۳) ممیزی امنیت (تازه، این نوبت)

| حوزه | وضعیت | جزئیات |
|---|---|---|
| **هش رمز عبور** | ✅ | PBKDF2-HMAC-SHA256 (سازگار با Django)، تعداد تکرار مطابق توصیهٔ OWASP ۲۰۲۳، ارتقای خودکار هش‌های قدیمی هنگام ورود (`needs_rehash`) |
| **JWT** | ✅ | HS256، دسترسی کوتاه‌مدت + رفرش چرخشی تک‌مصرف، jti هش‌شده در DB و قابل ابطال؛ استفادهٔ مجدد از رفرش ابطال‌شده = ابطال کل نشست‌های کاربر (سیگنال نفوذ) |
| **تفکیک دو صفحهٔ هویتی** | ✅ | ادمین (`admin_users`/`admin_sessions`/کوکی‌های `vitrin_admin_*`) کاملاً جدا از مشتری (`users`/`auth_sessions`/کوکی‌های `vitrin_*`)؛ هیچ کد مشترکی بین دو مسیر داده/رمزنگاری نیست |
| **2FA (TOTP)** | ✅ | برای ادمین‌ها، با گارد replay (مرحلهٔ آخر پذیرفته‌شده ذخیره و رد می‌شود)، غیرفعال‌سازی نیازمند رمز + کد زنده هم‌زمان |
| **قفل حساب** | ✅ | شمارندهٔ تلاش ناموفق + قفل زمانی، هم مشتری هم ادمین، هم برای رمز غلط هم TOTP غلط |
| **جلوگیری از شمارش حساب (enumeration)** | ✅ | پاسخ reset/verify همیشه عمومی (`{"status":"accepted"}`) صرف‌نظر از وجود ایمیل |
| **CSRF** | ✅ | `CsrfMiddleware` روی کوکی‌های httpOnly، توکن قابل‌خواندن جدا؛ تست مجزا برای عدم تداخل کوکی ادمین/مشتری |
| **نرخ‌محدودسازی (Rate limiting)** | ✅ | سه لایه: IP روی auth عمومی (`authip:`/`adminauthip:`)، per-tenant روی `/v1/*` (`get_rate_limiter`)؛ Redis-backed، fail-open مستند (طبق W4 قبلی) |
| **تزریق SQL** | ✅ | ۱۰۰٪ کوئری‌ها پارامتری (`$1، $2...`)؛ الگوهای `UPDATE ... SET {dynamic}` (plans/contact/kb/leads) نام ستون را همیشه از یک allowlist ثابت در کد می‌گیرند نه از ورودی کاربر — بازبینی صریح این نوبت، بدون یافتهٔ نگران‌کننده |
| **ایزولاسیون تنانت** | ✅ | همهٔ کوئری‌های سطح تنانت `tenant_id` را از principal احرازشده می‌گیرند، هرگز از پارامتر مسیر/بدنه؛ query-builder مرکزی جست‌وجو فیلتر `tenant_id` را اجباری می‌کند |
| **کلیدهای API** | ✅ | فقط هش (نه متن خام) در DB؛ کلید خام فقط یک‌بار در پاسخ ساخت برگردانده می‌شود |
| **رمزهای Provider AI** | ✅ | `api_key` در `ai_providers` write-only است — هر خواندن فقط ماسک‌شده (`…آخر۴رقم`) برمی‌گردد |
| **رمزهای مخفی در ریپو** | ✅ | بررسی `git ls-files` برای `.env`/`*secret*`/`*.pem`/`*.key` بدون فایل example → هیچ‌کدام commit نشده |
| **هدرهای امنیتی/HSTS/CORS/CSP** | ✅ | `SecurityHeadersMiddleware`: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, و **CSP** (`default-src 'none'; frame-ancestors 'none'` — سخت‌گیرانه چون این یک API خالص است، نه صفحهٔ HTML)؛ `CORS_ALLOW_ORIGINS` محدود به دامنهٔ واقعی (نه `*`) |
| **IP allowlist ادمین** | ✅ | میدل‌ور اختیاری `ADMIN_IP_ALLOWLIST` روی کل `/admin/*` |
| **XSS در فاکتور HTML** | ✅ | `html.escape` روی نام فروشگاه/توضیحات قبل از درج در قالب چاپی |
| **HMAC وب‌هوک** | ✅ | صورت‌حساب (`BILLING_WEBHOOK_SECRET`) و پلاگین‌های CMS (order webhook) هر دو HMAC-SHA256 با `compare_digest` (زمان‌ثابت) |
| **پرداخت** | ✅ | callback زرین‌پال چیزی را از روی خودِ ریدایرکت فعال نمی‌کند؛ verify سروری با مبلغ دقیق، replay-safe (سفارش paid دوباره فعال نمی‌شود) |
